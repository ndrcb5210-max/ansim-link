# 앱 콘텐츠 선언 (초안)

Play Console > 정책 > **앱 콘텐츠**의 항목들에 넣을 답변이다.
데이터 보안은 [data-safety.md](data-safety.md), 민감한 권한은
[permissions-declaration.md](permissions-declaration.md) 에 따로 적었다.

> Console 의 질문 문구와 선택지는 바뀐다. 아래와 다르면 **화면을 따른다.**
> 확인하지 못한 것은 `확인 필요` 로 적었다.

## 1. 대상 연령 및 콘텐츠 (Target audience and content)

### 선택: 만 16~17세, 만 18세 이상

| 연령 구간 | 선택 | 이유 |
| --- | --- | --- |
| 만 5세 이하 | 아니요 | |
| 만 6~8세 | 아니요 | |
| 만 9~12세 | 아니요 | |
| 만 13~15세 | **아니요** | 아래 설명 |
| 만 16~17세 | 예 | |
| 만 18세 이상 | 예 | |

**만 13~15세를 고르지 않는 이유.** 이 앱은 가입 때 만 14세 이상인지 확인한다
(위치정보법 제25조, 개인정보 보호법 제22조의2 — 만 14세 미만은 법정대리인 동의가 필요하고
이 앱은 그 절차를 만들지 않았다). 그런데 Play 의 연령 구간에는 '만 14~15세'가 없고
'만 13~15세'뿐이다. 그 구간을 고르면

- 만 13세도 대상으로 선언하는 셈이 되어 앱의 가입 요건과 어긋나고,
- Google Play **Families 정책**(아동 대상 앱) 요건이 따라붙는다. 이 앱은 아동을
  대상으로 만들지 않았고(CLAUDE.md 원칙 7), 가족 위치 공유 앱이 아동 대상 프로그램에
  들어가는 것은 맞지 않다고 봤다.

그래서 **만 16세 이상으로 선언하고**, 법이 허용하는 만 14~15세는 가입은 되지만 스토어
대상 연령에는 포함하지 않는 쪽을 골랐다. 이쪽이 '아동 대상 앱이 아니다'를 분명히 한다.

`확인 필요`: 선언한 대상 연령(16+)보다 앱의 가입 요건(14+)이 낮은 것이 Play 정책상
문제가 되는지 확인하지 못했다. 반대 방향(선언이 낮고 요건이 높은 것)보다는 안전하다고
보지만, 심사에서 지적되면 가입 요건을 16세로 올리는 것도 방법이다.

### 아동의 관심을 끄는 요소

- **아니요.** 캐릭터, 만화풍 그림, 밝은 색 위주 디자인, 아동용 음악·효과음이 없다.
  화면은 Material 3 기본 스타일이고 글 위주다.

### 스토어 등록정보에 아동이 흥미를 느낄 내용이 있는지

- **아니요.**

## 2. 콘텐츠 등급 설문 (IARC)

설문은 IARC 가 운영하고, 답변을 넣으면 지역별 등급(ESRB, PEGI, GRAC 등)이 **자동으로**
계산된다. 그래서 '예상 등급'을 여기에 적지 않는다. 아래는 **답변 초안**이다.

| 질문 범주 | 답변 | 메모 |
| --- | --- | --- |
| 앱 카테고리 | 참조, 뉴스 또는 교육 / 유틸리티 | `확인 필요` — Console 이 주는 카테고리 목록에서 고른다 |
| 폭력 | 없음 | |
| 성적 내용 | 없음 | |
| 비속어 | 없음 | |
| 통제 물질(술·담배·마약) | 없음 | |
| 도박 | 없음 | |
| 공포·무서운 내용 | 없음 | 재난문자 본문을 보여 주지만 등급 설문에서 말하는 연출된 공포가 아니다 |
| **사용자 간 상호작용** | **예** | 그룹 구성원끼리 안심 메시지를 주고받는다 |
| 상호작용 내용의 공개 범위 | 그룹 구성원만 | 공개 게시나 모르는 사람과의 연결이 없다 |
| **사용자의 물리적 위치 공유** | **예** | 이 설문에서 가장 중요한 답이다. 숨기면 안 된다 |
| 디지털 구매 | **예** | 월 구독(`premium_monthly`) |
| 사용자 생성 콘텐츠(UGC) 신고 기능 | **아니요** | 아래 메모 |

**위치 공유에 '예'를 하면 등급이 올라갈 수 있다.** 그래도 '예'로 답한다. 실제로 위치를
공유하는 앱이고, 설문을 사실과 다르게 답하는 것은 등급이 올라가는 것보다 훨씬 나쁜 일이다
(허위 답변은 앱 정지 사유다).

**UGC 신고 기능이 없는 것에 대한 메모.** 안심 메시지는 자기 그룹 구성원에게만 가고,
그룹에는 초대 코드로만 들어온다. 모르는 사람이 보낼 수 있는 길이 없어서 신고 기능을
두지 않았다. Play 의 UGC 정책은 '사용자가 공개적으로 콘텐츠를 올릴 수 있는 앱'에
신고·차단 수단을 요구하는데, 이 앱이 거기에 해당하는지는 `확인 필요`.
해당한다면 그룹 구성원 차단(= 그룹에서 내보내기) 기능을 만들어야 한다.
지금은 당사자가 '동의 철회'로 그룹에서 나가는 것만 된다.

## 3. 광고

- **이 앱에는 광고가 없습니다.** → '아니요'를 고른다.
- 광고 SDK 를 하나도 넣지 않았다.
- **광고 ID(AD_ID) 권한도 없다.** targetSdk 33 이상에서 광고 ID 를 쓰려면
  `com.google.android.gms.permission.AD_ID` 를 선언해야 하는데, 병합된 릴리스 매니페스트에
  그 권한이 없는 것을 확인했다(`app/build/intermediates/packaged_manifests/release/`).
  Firebase Analytics 를 넣지 않았기 때문이다.

## 4. 앱 액세스 권한 (App access)

**'모든 기능이 제한 없이 제공되지 않습니다'를 고르고 테스트 계정을 줘야 한다.**
이 앱은 로그인하지 않으면 그룹·공유·설정을 쓸 수 없어서, 심사자가 로그인할 방법이 없으면
'기능을 확인할 수 없음'으로 거절된다. 자주 빠뜨리는 항목이다.

넣을 내용(초안):

| 항목 | 값 |
| --- | --- |
| 이름 | 전체 기능(로그인 필요) |
| 로그인에 필요한 정보 | 이메일, 비밀번호 |
| 사용자 이름 | `[심사용 계정 이메일]` |
| 비밀번호 | `[심사용 계정 비밀번호]` |
| 기타 안내 | 아래 '심사자 안내문' |

### 심사자 안내문 (초안)

```
이 앱은 휴대폰이 받은 재난문자 알림을 읽어 위치 공유를 시작할지 묻습니다.
재난문자를 기다리지 않고도 위치 공유 기능 전체를 확인하실 수 있습니다.

확인 순서
1. 위 계정으로 로그인합니다(또는 직접 가입하실 수 있습니다. 만 14세 이상 확인과
   약관 동의가 필요합니다).
2. 그룹 > 그룹 만들기 로 안심 그룹을 만듭니다. 초대 코드를 만들면 다른 계정으로
   참여해 '위치 제공 동의' 화면을 보실 수 있습니다.
3. 홈 화면의 '지금 공유' 를 누르면 위치 공유가 바로 시작됩니다. 누르기 전에 위치 권한이
   왜 필요한지 설명하는 화면이 먼저 나옵니다. 공유가 시작되면 상시 알림과 홈 화면
   배너가 항상 보입니다.
4. 공유 중에는 홈 화면 배너와 알림의 '지금 중지' 로 즉시 끝낼 수 있습니다.
   끝내지 않아도 정해진 시간(기본 60분)이 지나면 자동으로 끝납니다.
5. 설정 > 내 위치 제공 기록 에서 '누구에게·언제·무슨 목적으로' 제공했는지 보실 수 있습니다.
6. 그룹 화면 > 내 공유 상태 에서 '일시중지'와 '동의 철회'를 한 번에 하실 수 있습니다.

재난문자 감지 자체를 확인하시려면
7. 설정 > 재난문자 감지 에서 왜 알림 접근 권한이 필요한지 설명을 보시고 권한을 켭니다.
   (사이드로드한 빌드에서는 Android 13 이상의 '제한된 설정' 때문에
    앱 정보 > 더보기 > 제한된 설정 허용 을 먼저 눌러야 합니다.)
8. 실제 재난문자가 오면 "가족에게 내 위치를 공유할까요?" 알림이 뜨고,
   [공유 시작] 을 눌렀을 때 공유가 시작됩니다. 재난문자가 오지 않아도 3번의 '지금 공유'로
   같은 공유 기능을 확인하실 수 있습니다.

참고: 위치 공유는 '한 번 눌러 시작'이 기본입니다. 설정 > 위치 공유 > 자동 시작 을 켜면
명시적 공개 화면과 백그라운드 위치 권한 요청을 거친 뒤 자동 시작으로 바뀝니다.
```

**'테스트 발동' 버튼을 안내문에 쓰지 않았다.** 그 버튼은 릴리스 빌드에 없다 —
`AnsimLinkApp.kt` 가 설정 화면의 디버그 항목을 `showDebugEntries = BuildConfig.DEBUG` 로
가린다(확인했다). 그래서 심사자가 볼 수 있는 길로만 안내문을 적었다. 홈 화면의
'지금 공유'가 발동 알림을 누른 것과 같은 경로(`ShareController`)를 지나므로 위치 공유
기능 자체는 그대로 확인된다.

`확인 필요`: 그래도 '재난문자를 받았을 때'의 알림은 심사자가 재현하기 어렵다. 심사에서
그 점이 문제가 되면 릴리스에도 테스트 발동을 두는 것을 생각한다(설정 안쪽에 두고
'테스트용'이라고 적는 식). 지금은 [permissions-declaration.md](permissions-declaration.md) 의
시연 영상이 그 장면을 대신한다.

### 공공기관 앱이 아니다

Google Play 는 공공기관을 대표하거나 공공기관과 제휴한 것처럼 보이는 앱에 별도 요건을
둔다. 이 앱은 개인이 만든 앱이고 어떤 기관과도 관계가 없다. 그래서

- 앱 이름에 기관 이름이나 '재난안전', '국민' 같은 공공 서비스 느낌의 말을 넣지 않는다,
- 스토어 설명 첫 덩어리에 '공공기관이 만든 앱이 아니며 어떤 기관과도 제휴하거나
  승인받지 않았습니다'를 적는다([store-listing.md](store-listing.md)),
- 행정안전부 재난구분 어휘를 분류에 쓰지만(공개된 API 규격) 그 사실을 기관의 보증처럼
  적지 않는다.

### 응급 서비스처럼 적지 않는다

119·112 를 대신하거나 구조 요청을 보내는 앱이 아니다. 스토어 설명과 앱 화면에
'긴급한 상황에서는 119와 재난문자, 지자체 안내를 따르세요'를 적는다.
`확인 필요`: Play 에 응급 대응 기능을 주장하는 앱에 대한 별도 정책이 있는지는
확인하지 못했다. 어차피 그런 기능이 없으므로 그렇게 적지 않는 것으로 피한다.
