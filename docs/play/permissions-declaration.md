# 민감한 권한 선언 문구와 시연 영상 대본 — 초안

Play Console > 정책 > 앱 콘텐츠 의 **민감한 앱 권한**(위치)과 **포그라운드 서비스**
항목에 넣을 답변, 그리고 두 항목이 요구하는 시연 영상 대본이다.

> Console 의 질문 문구는 바뀐다. 아래는 답변의 **내용**을 미리 적어 둔 것이고, 화면의
> 질문과 글자 수 제한에 맞춰 줄이거나 나눠 넣는다. 확인하지 못한 것은 `확인 필요`.

## 0. 이 앱이 위치를 쓰는 방식 — 두 가지 모드

선언서를 쓰기 전에 이 구분이 먼저다. **기본 모드에는 백그라운드 위치가 필요 없다.**

| 모드 | 어떻게 시작하나 | 백그라운드 위치 | 기본값 |
| --- | --- | --- | --- |
| 한 번 눌러 시작 | 재난문자를 감지하면 알림을 띄우고, 사용자가 [공유 시작]을 누를 때 시작 | **필요 없음** | **켜짐** |
| 자동 시작 | 재난문자를 감지하면 바로 시작 | 필요함 | 꺼짐(사용자가 켠다) |

자동 시작을 켜지 않은 사용자에게는 `ACCESS_BACKGROUND_LOCATION` 권한을 **요청하지
않는다.** 권한이 없으면 자동 시작은 저절로 꺼지고 기본 모드로 돌아간다
(`domain/share/AutoStartFlow.kt` 의 `effectiveMode`).

## 1. 백그라운드 위치 권한 선언서 (답변 초안)

### 이 권한을 쓰는 기능 이름

```
자동 시작 (선택 기능) — 재난문자를 받았을 때 위치 공유를 자동으로 시작
```

### 이 기능이 사용자에게 주는 이점 / 왜 필요한가

```
이 앱은 휴대폰이 재난문자(위급재난문자·긴급재난문자·안전안내문자)를 받으면, 사용자가
미리 만들어 둔 '안심 그룹'의 구성원에게 사용자의 위치를 정해진 시간 동안 공유합니다.
가족이 서로의 안전을 확인하는 기능입니다.

기본 설정에서는 재난문자를 감지하면 알림을 띄우고, 사용자가 [공유 시작]을 누를 때만
공유를 시작합니다. 이 경우 백그라운드 위치 권한은 쓰지 않습니다.

'자동 시작'은 사용자가 설정에서 직접 켜는 선택 기능입니다. 재난문자는 사용자가 휴대폰을
보고 있지 않을 때(잠든 시간, 운전 중, 지진으로 대피하는 중) 오는 일이 많고, 그때 알림을
눌러 줄 사람이 없으면 가족은 아무 소식도 받지 못합니다. 이 기능을 켠 사용자는 앱이
닫혀 있거나 사용 중이 아닐 때도 재난문자를 감지한 순간 위치 공유가 시작되기를 선택한
것입니다. 그러려면 앱이 포그라운드에 없는 상태에서 위치 수집을 시작해야 하므로
ACCESS_BACKGROUND_LOCATION 이 필요합니다.
```

### 포그라운드 위치만으로는 안 되는 이유

```
재난문자 알림은 사용자가 앱을 보고 있지 않을 때 도착합니다. 알림 접근 서비스
(NotificationListenerService)는 백그라운드에서 깨어나므로 감지 자체는 되지만,
그 상태에서 위치 포그라운드 서비스를 시작하려면 백그라운드 위치 권한이 필요합니다.
권한이 없으면 시작이 거부되고(ForegroundServiceStartNotAllowedException 또는
SecurityException), 앱은 '눌러서 시작' 알림으로 대신합니다. 즉 사용자가 알림을 누를 수
없는 상황에서는 공유가 시작되지 않습니다. 그 상황을 사용자가 미리 선택해 없애는 것이
'자동 시작' 기능입니다.
```

### 위치 수집 빈도와 보관

```
위치는 공유 세션 동안에만 수집합니다. 세션은 기본 60분(설정 30~180분) 뒤 자동으로
끝나고, 사용자는 알림이나 앱 화면의 '지금 중지'로 즉시 끝낼 수 있습니다.
세션 중에는 60초 간격으로 확인하고 직전 위치에서 50m 이상 움직였을 때만 기록하며,
움직이지 않아도 5분마다 한 번은 기록합니다(앱이 멈춘 것과 구분하기 위함).
이동 경로를 쌓지 않습니다 — 구성원별 마지막 위치 1건만 둡니다. 세션이 끝나면 그
1건만 남기고 24시간 뒤 지웁니다. 사용자가 동의를 철회하거나 일시중지하면 즉시 지웁니다.
```

### 명시적 공개(prominent disclosure)를 어떻게 하는가

```
'자동 시작' 스위치를 누르면, 시스템 권한 요청 화면보다 **먼저** 앱 안의 대화상자가
뜹니다. 그 화면에 다음을 적습니다.

- "자동 시작을 켜면, 앱이 닫혀 있거나 사용하지 않을 때도 재난문자를 받으면 안심연결이
  내 위치를 수집해 안심 그룹 구성원에게 공유합니다."
- 이 위치를 쓰는 기능 목록(그룹 구성원에게 실시간 위치 공유, 가족 위치 보기의 거리 계산)
- "위치는 이 두 가지 외에 어디에도 쓰지 않습니다. 광고나 분석에 쓰지 않고 다른 회사에
  넘기지 않습니다."
- "자동 시작은 선택입니다. 켜지 않아도 알림을 눌러 공유를 시작할 수 있습니다."

사용자가 [이해했습니다, 계속]을 눌러야 권한 요청으로 넘어갑니다. 뒤로 가기나 화면 밖을
누르는 것은 동의로 보지 않습니다. 권한을 주지 않으면 자동 시작은 꺼진 상태로 남고
앱은 기본 모드('한 번 눌러 시작')로 동작합니다.
```

위 문구는 앱의 실제 문자열이다(`res/values/strings.xml` 의 `auto_start_disclosure_*`).
선언서에 적은 글과 앱 화면의 글이 다르면 그것만으로 지적 사유가 된다.

**순서가 요건이다.** Play 는 백그라운드 위치에 대해 런타임 권한 요청 **전에** 뜨는
대화상자 형태의 명시적 공개를 요구한다(Play Console 고객센터 answer/9799150).
이 앱은 `AutoStartFlow.nextStep()` 이 단계를 정하고 화면은 그 단계 하나만 보여 준다 —
공개 화면을 건너뛰고 권한 버튼을 먼저 누를 수 있는 길을 만들지 않았다(4단계 devlog).

### 시연 영상

아래 2항의 대본으로 찍어 YouTube **미등록(unlisted)** 으로 올리고 그 URL 을 넣는다.
`확인 필요`: 영상 길이·형식 제한(공개 범위, 자막 필요 여부)은 Console 화면에서 확인한다.

## 2. 포그라운드 서비스 선언 (type = location)

Play Console 의 포그라운드 서비스 항목에 `location` 타입 하나를 선언한다.

### 어떤 기능에 쓰는지 (답변 초안)

```
사용자가 시작한 위치 공유입니다. 사용자가 안심 그룹 구성원에게 자신의 위치를 정해진
시간 동안 실시간으로 공유하면, 그동안 위치 포그라운드 서비스가 돌아갑니다.
서비스가 도는 동안 해제할 수 없는 상시 알림이 항상 보이고, 그 알림에 '지금 중지'
버튼이 있습니다. 앱 안에도 공유 중 배너와 중지 버튼이 보입니다.
공유가 끝나면(시간 만료, 사용자 중지, 동의 철회) 서비스도 함께 멈춥니다.
```

Play 는 `location` 타입의 적절한 사용 예로 **"Find My Friend" 기능**(사용자가 시작한
위치 공유)을 든다(answer/13392821). 이 앱의 쓰임이 그 예와 같은 종류다.

### 시작 경로

| 경로 | 사용자 동작 | 메모 |
| --- | --- | --- |
| 발동 알림의 [공유 시작] | 알림을 누름 | 기본 모드 |
| 홈 화면의 [지금 공유] | 버튼을 누름 | 앱을 열고 직접 시작 |
| 자동 시작 | 미리 설정에서 켜 둠 | 선택 기능. 백그라운드 위치가 있어야 동작 |

### 시연 영상

Play 는 `location` 타입 선언의 영상에 **사용자가 위치 공유를 시작하는 장면**이 나와야
한다고 적고 있다(answer/13392821). 아래 대본의 0:18~0:26 구간이 그 장면이다.
백그라운드 위치 선언서와 **같은 영상 하나**로 두 요건을 같이 보여 준다.

## 3. 시연 영상 대본 (30초)

촬영: 실기기 화면 녹화. 소리는 없어도 되고, 각 장면에 한국어 자막을 넣는다.
`확인 필요`: 영어 자막이나 음성이 필요한지는 Console 화면에서 확인한다.

| 시각 | 화면 | 자막 |
| --- | --- | --- |
| 0:00–0:03 | 앱을 열어 홈 화면. 안심 그룹 이름과 구성원 수가 보인다 | 안심연결 — 재난문자를 받으면 안심 그룹에 위치를 공유합니다 |
| 0:03–0:06 | 설정 > 위치 공유 로 이동, '자동 시작' 스위치를 누른다 | 선택 기능 '자동 시작'을 켭니다 |
| 0:06–0:14 | **명시적 공개 대화상자**가 뜬다. 천천히 스크롤해 전문이 보이게 한다. "앱이 닫혀 있거나 사용하지 않을 때도 … 위치를 수집해 공유합니다" 문장에서 2초 멈춘다 | 권한을 요청하기 **전에** 왜 필요한지 먼저 보여 줍니다 |
| 0:14–0:18 | [이해했습니다, 계속] → 시스템 위치 권한 요청 → 허용 → 백그라운드 위치('항상 허용') 설정 화면으로 이동해 허용 | 사용자가 확인한 뒤에 권한을 요청합니다 |
| 0:18–0:26 | 홈으로 돌아와 **[지금 공유]를 누른다.** 공유가 시작되고 상단에 상시 알림, 홈에 공유 중 배너와 남은 시간이 보인다 | 위치 공유는 사용자가 시작하고, 공유 중에는 항상 알림이 보입니다 |
| 0:26–0:30 | 알림을 내려 **[지금 중지]** 를 누른다. 공유가 끝나고 배너가 사라진다 | 한 번 눌러 바로 멈출 수 있습니다 |

### 이 대본이 꼭 담아야 하는 것 (빠지면 다시 찍는다)

1. **권한 요청 전에 뜨는 명시적 공개 대화상자**와 그 안의 '앱을 사용하지 않을 때도
   수집한다'는 문장 (백그라운드 위치 요건)
2. **사용자가 위치 공유를 시작하는 동작** (포그라운드 서비스 location 요건)
3. 공유 중 **상시 알림**이 보이는 장면
4. **중지**가 한 번에 되는 장면
5. 앱 이름이 화면에 보이는 장면(어느 앱인지 알 수 있게)

### 찍을 때 주의

- 실제 가족의 이름·좌표가 보이지 않게 테스트 계정과 테스트 그룹으로 찍는다.
- 지도를 띄우지 않는다(이 앱은 지도 SDK 를 쓰지 않는다). 구성원 목록과 거리만 보인다.
- 재난문자를 기다릴 수 없으므로 발동 알림 장면은 넣지 않았다. 대신 [지금 공유]로
  같은 공유 경로를 보여 준다(둘 다 `ShareController` 를 지난다).
  `확인 필요`: 심사가 '재난문자 감지 → 알림' 장면을 요구하면 디버그 빌드의
  '테스트 발동'으로 찍은 장면을 덧붙인다. 그 경우 디버그 빌드로 찍은 영상이어도 되는지
  확인할 것.

## 4. 알림 접근 권한 (NotificationListenerService)

이 앱의 재난문자 감지는 `BIND_NOTIFICATION_LISTENER_SERVICE` 서비스로 한다.
일반 앱은 한국 재난문자 채널(4370~4392)의 셀 브로드캐스트를 직접 받을 수 없다
(`RECEIVE_EMERGENCY_BROADCAST` 는 signature|privileged 권한).

`확인 필요`: Play Console 에 알림 접근을 위한 **별도 선언 양식이 있는지** 확인하지 못했다
(SMS·통화 기록, 모든 파일 접근, 접근성 서비스처럼). 양식이 없더라도 심사에서 질문이
올 수 있으니 답변을 미리 적어 둔다.

```
안심연결은 휴대폰의 재난문자 앱이 띄운 알림을 읽어 재난문자인지 판단합니다. 일반 앱은
재난문자(셀 브로드캐스트)를 직접 수신할 수 없어 다른 방법이 없습니다.

읽는 범위를 좁혔습니다.
- 허용 목록에 있는 재난문자 앱의 알림만 봅니다
  (com.google.android.cellbroadcastreceiver, com.android.cellbroadcastreceiver,
   com.android.cellbroadcastreceiver.module).
- 목록 밖의 알림은 서비스 안에서 곧바로 버립니다.
- 재난문자 알림에서 읽는 것은 제목(문자 종류 판단)과 본문(재난 유형 분류)입니다.
- 재난문자 알림의 내용은 **기기 안에만** 저장합니다(발동 기록, 본문 앞 60자, 30일).
  서버로 보내지 않습니다. 그룹에 보내는 안심 메시지에는 문자 종류와 재난 유형만 들어갑니다.
- 다른 앱의 알림 내용은 저장하지도, 서버로 보내지도 않습니다.
- 권한은 사용자가 시스템 설정에서 직접 켜야 하고, 왜 필요한지 설명하는 화면을 먼저
  보여 줍니다. 권한을 켜지 않아도 앱의 다른 기능은 그대로 쓸 수 있습니다.

문자(SMS)는 읽지도 보내지도 않습니다. SMS 권한을 요청하지 않습니다.
```

## 5. 라이브러리가 더하는 권한 (스토어의 권한 목록에 같이 보인다)

매니페스트에 우리가 적은 권한 말고도, 라이브러리의 매니페스트가 병합돼 들어오는 권한이
있다. 스토어의 '권한' 목록과 설치 화면에는 **병합된 결과**가 보이므로 미리 알아 둔다.
아래는 병합된 릴리스 매니페스트를 직접 확인한 결과다
(`app/build/intermediates/packaged_manifests/release/`).

| 권한 | 들어온 곳 | 쓰임 |
| --- | --- | --- |
| `ACCESS_NETWORK_STATE` | Firebase, WorkManager | 네트워크 상태 확인 |
| `INTERNET` | Firebase | 서버 통신 |
| `WAKE_LOCK` | WorkManager, FCM | 작업·푸시 처리 중 깨어 있기 |
| `RECEIVE_BOOT_COMPLETED` | **WorkManager** | 아래 메모 |
| `USE_BIOMETRIC`, `USE_FINGERPRINT` | androidx.credentials | Credential Manager(Google 로그인) |
| `com.android.vending.BILLING` | Play Billing | 구독 결제 |
| `com.google.android.c2dm.permission.RECEIVE` | FCM | 푸시 수신 |
| `READ_GSERVICES` | Play 서비스 | |
| `...DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | androidx.core | 내부용(앱 자신만 쓰는 서명 권한) |

### `RECEIVE_BOOT_COMPLETED` 에 대한 메모

`app/src/main/AndroidManifest.xml` 의 주석에 **"RECEIVE_BOOT_COMPLETED 는 넣지 않는다.
재부팅 뒤 공유를 되살리지 않는다"** 고 적어 두었는데, 병합된 매니페스트에는 이 권한이
들어 있다. **WorkManager 가 자기 매니페스트에서 선언하기 때문이다**(재부팅 뒤 예약된
작업을 다시 등록하려고 쓴다).

적어 둔 방침 자체는 그대로 지켜진다 — 재부팅 뒤에 위치 공유가 되살아나는 코드는 없고,
`stopWithTask="true"` 라 앱을 치우면 공유도 멈춘다. 다만 **'우리가 선언하지 않았다'와
'앱에 그 권한이 없다'는 다른 말이다.** 스토어에서 권한 목록을 보는 사용자에게는
병합된 결과만 보인다. 질문이 오면 위 표로 답한다.

`확인 필요`: 안심 메시지 발송 작업(`SafetyMessageWorker`)이 재부팅을 건너 살아남아야
하는지 생각해 볼 일이다. 지금은 WorkManager 기본 동작에 맡겨 두었다.
