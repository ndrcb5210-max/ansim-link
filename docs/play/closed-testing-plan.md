# 비공개 테스트 운영 계획 — 초안

Play Console > 테스트 및 출시 > 테스트 > **비공개 테스트**로 운영할 계획이다.

> **왜 해야 하나.** 개인(비조직) 개발자 계정으로 만든 새 앱은 프로덕션에 바로 출시할 수
> 없고, 비공개 테스트를 **테스터 12명 이상으로 14일 연속** 운영한 뒤 프로덕션 액세스를
> 신청해야 한다.
>
> `확인 필요`: 요건의 정확한 수치와 '연속'의 판정 기준(옵트인 상태를 유지한 테스터 수를
> 매일 세는지 등)은 Console 의 '프로덕션 액세스' 화면에 적혀 있다. 시작 전에 그 화면을
> 그대로 읽고 이 문서를 고친다. 아래는 12명·14일을 전제로 짠 계획이다.

## 1. 일정

| 날짜 | 할 일 |
| --- | --- |
| D-7 | 데이터 보안 양식·앱 콘텐츠 선언 제출(비공개 테스트에도 필요하다). 처리방침·삭제 안내 URL 공개 |
| D-5 | 실제 `google-services.json` 으로 서명된 AAB 를 올려 **내부 테스트**로 먼저 확인 |
| D-3 | 테스터 모집. 15명 이상 받아 둔다(12명이 최소선이라 여유가 필요하다) |
| D-1 | 비공개 테스트 트랙 생성, 이메일 목록 등록, 옵트인 링크 발송 |
| **D-0** | 테스터 12명 이상이 옵트인하고 설치한 것을 확인. 여기서부터 14일을 센다 |
| D+1 ~ D+13 | 매일 Console 에서 테스터 수 확인. 주 2회 피드백 요청 |
| D+7 | 중간 점검. 받은 의견 정리, 고칠 것 고르기 |
| D+14 | 14일 연속 충족 확인 → **프로덕션 액세스 신청** |

### 왜 15명 이상 받아 두나

테스터가 중간에 앱을 지우거나 옵트아웃하면 그날의 인원이 12명 아래로 떨어진다.
'연속 14일'이 끊기면 처음부터 다시 세야 할 수 있다. 세 명은 그 여유다.

`확인 필요`: 중간에 인원이 줄었을 때 기간이 초기화되는지, 줄어든 날만 빠지는지
확인하지 못했다. 안전하게 여유를 둔다.

## 2. 테스터 모집

### 모집 문구 (초안)

```
[안심연결] Android 앱 테스터를 찾습니다 (12명, 14일)

재난문자를 받으면 가족과 서로의 위치·안심 메시지를 나누는 Android 앱을 만들고 있습니다.
Google Play 출시 전 비공개 테스트에 참여해 주실 분을 찾습니다.

무엇을 하시게 되나요
- Google Play 에서 앱을 설치하고 14일 동안 지우지 말아 주세요(설치만 유지해 주시면 됩니다).
- 2~3명씩 '안심 그룹'을 만들어 보고, 위치 공유를 한 번씩 켜 보세요.
- 이상한 점이나 불편한 점을 아래 방법으로 알려 주세요.

꼭 알아 두실 것 (중요)
- 이 앱은 **위치를 공유하는 앱**입니다. 공유를 시작하면 내 위치(위도·경도·시각)가
  같은 그룹 구성원에게 전달됩니다. 동의하지 않으면 전달되지 않습니다.
- 공유는 내가 시작할 때만 시작하고, 정해진 시간(기본 60분) 뒤 자동으로 끝납니다.
  공유 중에는 알림이 항상 보이고 '지금 중지'로 바로 멈출 수 있습니다.
- 동의는 언제든 철회·일시중지할 수 있고 바로 반영됩니다.
- 재난문자 감지는 휴대폰 기종·통신사·설정에 따라 **동작하지 않을 수 있습니다.**
  긴급한 상황에서는 119와 재난문자, 지자체 안내를 따르세요.
- 만 14세 이상만 가입할 수 있습니다.
- 테스트 중 수집하는 것: 가입 이메일, 닉네임, (공유를 켠 동안의) 위치.
  자세한 것은 개인정보 처리방침을 봐 주세요. [처리방침 URL]
- 테스트가 끝난 뒤 계정은 앱에서 직접 지울 수 있습니다(설정 > 계정 > 계정 삭제).

참여하시려면
Google 계정 이메일 주소를 [모집 폼 URL] 또는 [고객문의 이메일] 로 보내 주세요.
그 이메일로 설치 링크를 보내 드립니다.

기간: [시작일] ~ [종료일] (14일)
문의: [고객문의 이메일]
```

**'위치를 공유하는 앱'을 모집 문구 앞쪽에 적는다.** 모집 단계에서 숨기고 설치 뒤에 알리면
그게 곧 스토커웨어 앱의 모양이다. 참여를 망설이게 되더라도 먼저 적는다.

**친구·가족에게 부탁하는 것이 현실이다.** 이 앱은 2명 이상이 같은 그룹에 있어야 기능이
돌아가므로, 서로 아는 사람 몇 묶음으로 모으는 편이 테스트가 된다. 모르는 사람 12명을
모아 각자 혼자 쓰게 하면 '그룹에 나 혼자'인 상태만 테스트된다.

### 설치 안내 문구 (옵트인 링크와 함께 보낼 내용)

```
안심연결 테스트에 참여해 주셔서 고맙습니다.

1) 아래 링크를 **테스터로 등록된 Google 계정**으로 열어 '테스터가 되기'를 눌러 주세요.
   [옵트인 링크]
2) 그 화면의 'Google Play 에서 다운로드'로 설치해 주세요.
3) 앱을 열고 가입합니다(이메일 또는 Google 로그인). 만 14세 이상 확인과 약관 동의가
   필요합니다.

처음에 꼭 해 보실 것
- 그룹 > 그룹 만들기 로 그룹을 만들고, 초대 코드를 같이 테스트하실 분에게 보내 주세요.
- 초대받은 분은 '위치 제공 동의' 화면에서 누구에게 제공되는지 확인하고 동의해 주세요.
- 홈의 '지금 공유'를 눌러 위치 공유를 켜 보고, 상대방 화면에 내 위치가 보이는지
  확인해 주세요. 끝나면 '지금 중지'를 눌러 주세요.
- 설정 > 재난문자 감지 에서 알림 접근 권한을 켜 주세요.
  (이 권한이 없으면 재난문자를 감지하지 못합니다.)
- 설정 > 내 위치 제공 기록 에서 방금 공유한 기록이 남았는지 봐 주세요.

알려 주시면 좋은 것
- 안 되는 것, 멈추는 것, 알 수 없는 문구
- 권한을 켜는 과정에서 막힌 곳
- 재난문자가 실제로 왔을 때 알림이 떴는지 / 안 떴는지 (기종과 통신사를 같이 적어 주세요)
- '이건 좀 불편하다' 싶은 것

보내실 곳: [피드백 폼 URL] 또는 [고객문의 이메일]

부탁: 14일 동안 앱을 지우지 말아 주세요. 출시 심사 요건이라 중간에 지우면 기간이
처음부터 다시 시작됩니다. 쓰지 않으셔도 설치만 유지해 주시면 됩니다.
```

### 실기기 재난문자 패키지 확인 부탁 (일부 테스터에게)

삼성 기기의 재난문자 앱 패키지 이름을 확인하지 못해 허용 목록에 넣지 못했다
(1~5단계부터 남은 일). 디버그 빌드에는 '받은 알림 패키지 기록' 화면이 있다.

```
삼성 갤럭시를 쓰시는 분께 한 가지 더 부탁드립니다.
재난문자가 실제로 왔을 때 앱이 감지하지 못하면, 그 기기의 재난문자 앱 이름이 저희
목록에 없는 것일 수 있습니다. 기종(예: 갤럭시 S24)과 통신사, 그리고 감지됐는지
여부만 알려 주세요.
```

`확인 필요`: 그 화면은 디버그 빌드에만 있어서(`BuildConfig.DEBUG`) Play 로 받은 테스트
빌드에서는 쓸 수 없다. 패키지 이름을 받으려면 ① 따로 디버그 APK 를 보내거나
② 릴리스 빌드에도 그 화면을 두어야 한다. 결과를
[../RELEASE_CHECKLIST.md](../RELEASE_CHECKLIST.md) 의 기록란에 적는다.

### 폼 질문 (초안)

1. 기종과 Android 버전, 통신사 (예: 갤럭시 S23 / Android 15 / SKT)
2. 어디까지 해 보셨나요? (가입 / 그룹 만들기 / 참여 / 위치 공유 / 안심 메시지 / 제공 기록)
3. 안 되거나 멈춘 것이 있었나요? 어느 화면에서였나요?
4. 알 수 없는 문구나 설명이 부족한 화면이 있었나요?
5. 권한을 켜는 과정에서 막힌 곳이 있었나요? (알림 접근 / 위치 / 백그라운드 위치)
6. 재난문자가 실제로 온 적이 있나요? 있으면 앱이 알림을 띄웠나요?
7. 위치가 공유되는 동안 '지금 공유 중'이라는 것을 알 수 있었나요?
8. 이 앱을 가족에게 권하시겠습니까? 그 이유는?
9. 그 밖에 하고 싶은 말

7번을 일부러 넣었다. CLAUDE.md 원칙 2('숨기지 않는다')가 정말 지켜지는지는 **쓰는
사람이 알아차렸는지**로만 확인된다. 상시 알림을 띄운 것으로는 모자랄 수 있다.

### 기록 방법

받은 의견은 `docs/devlog/07-closed-testing.md`(아직 없다)에 날짜·기종·내용·조치로 적는다.
프로덕션 신청서의 2번 질문이 "의견을 바탕으로 무엇을 바꿨는지"를 묻기 때문에, 그때
찾을 수 있게 모아 둬야 한다.

## 4. 프로덕션 액세스 신청서 답변 (초안)

신청서는 세 가지를 묻는다. `확인 필요`: 아래 질문 문구는 기억에 의존해 적은 것이라
Console 화면과 다를 수 있다. **화면의 질문을 그대로 읽고 답을 맞춘다.**

> 아래 답변에는 `[ ]` 가 많다. **테스트를 하지 않았으니 결과를 적을 수 없다.**
> 틀을 먼저 만들어 두고 테스트가 끝난 뒤 사실로 채운다. 지어내서 채우지 않는다.

### 1) 앱을 어떻게 테스트했는지

```
[시작일]부터 [종료일]까지 14일 동안 비공개 테스트를 운영했고, 매일 [N]명의 테스터가
앱을 설치한 상태를 유지했습니다(최대 [N]명).

테스터는 가족·지인 [N]개 묶음으로 모았습니다. 이 앱은 2명 이상이 같은 '안심 그룹'에
있어야 기능이 동작해서, 서로 아는 사람끼리 묶지 않으면 '그룹에 나 혼자'인 상태만
테스트됩니다.

테스터에게 요청한 확인 항목
- 가입(이메일/Google 로그인), 만 14세 이상 확인, 약관 4종 동의
- 그룹 만들기, 초대 코드 발급, 코드로 참여, 위치 제공 동의 화면
- 위치 공유 시작·중지, 공유 중 상시 알림과 배너 확인, 자동 종료
- 안심 메시지 편집과 발송, 다른 구성원의 수신 확인
- 내 위치 제공 기록 확인, 일시중지, 동의 철회
- 알림 접근 권한 설정, 재난문자 수신 시 감지 여부(기종·통신사와 함께 기록)
- 구독 결제 흐름(라이선스 테스터 계정), 프리미엄 한도 적용
- 계정 삭제

기기 범위: [기종 목록] / Android [버전 범위] / 통신사 [목록]

자동 검사도 함께 돌렸습니다. 단위 테스트 [N]개와 화면 스크린샷 테스트 [N]장,
Firestore 보안 규칙 테스트 [N]개를 GitHub Actions 에서 커밋마다 돌립니다.
Android vitals 에서 크래시·ANR 을 매일 확인했습니다.
```

### 2) 테스터의 의견과 그에 따라 바꾼 것

```
받은 의견 [N]건 중 주요한 것과 조치입니다.

| 의견 | 조치 |
| --- | --- |
| [의견] | [무엇을 어떻게 고쳤는지, 어느 버전에 들어갔는지] |

(테스트가 끝난 뒤 사실로 채운다. 고치지 않기로 한 것은 그 이유도 적는다 —
'의견을 받았지만 고치지 않았다'도 정직한 답이고, 이유가 있으면 문제가 되지 않는다.)
```

### 3) 프로덕션에 출시할 준비가 됐다고 보는 이유

```
- 14일 동안 [N]명이 쓰면서 앱이 멈추거나 데이터가 어긋나는 문제가 [N]건 보고됐고
  모두 고쳐 [버전]에 반영했습니다. 마지막 [N]일 동안 새 크래시는 없었습니다.
  (Android vitals: 크래시 없는 세션 [N]%)
- 정책이 요구하는 것을 모두 채웠습니다. 데이터 보안 양식, 백그라운드 위치 선언서와
  시연 영상, 포그라운드 서비스(location) 선언, 개인정보 처리방침과 계정 삭제 URL 공개,
  대상 연령·콘텐츠 등급 설문.
- 위치 처리에 대해 지키는 것: 위치 공유는 사용자가 시작할 때만 시작하고(기본 모드),
  공유 중에는 해제할 수 없는 알림이 항상 보이며, 정해진 시간 뒤 자동으로 끝납니다.
  동의 철회와 일시중지는 한 번 눌러 즉시 반영됩니다. 위치는 공유 세션 동안만 기록하고
  이동 경로를 쌓지 않으며, 세션이 끝나면 마지막 1건만 남겨 24시간 뒤 지웁니다.
- 국내 법령 사항: 만 14세 이상 가입 확인, 위치정보 수집·이용 동의와 제3자 제공 동의를
  나눠 받기, 제공 시마다 통보와 제공 기록 열람(위치정보법 제19조③),
```
