# 데이터 보안 (Data safety) 항목표 — 초안

Play Console > 정책 > 앱 콘텐츠 > **데이터 보안**에 넣을 답변이다.

> **이 양식은 비공개 테스트·공개 테스트 트랙에도 필요하다.** 내부 테스트만 할 때는
> 예외지만, 비공개 테스트(프로덕션 신청에 필요한 14일 테스트)를 시작하려면 먼저 끝내야 한다.
> (Play Console 고객센터 answer/10787469)

## 0. 이 표를 만든 방법

앱이 기기 밖으로 보내는 데이터를 코드에서 직접 훑어 적었다. 근거는 두 곳이다.

- `app/src/main/kotlin/.../data/FirestoreSchema.kt` — Firestore 에 쓰는 컬렉션과 필드 전부
- `app/src/main/kotlin/.../data/alert/AlertEventEntity.kt` — 기기 안에만 두는 것

**Play 의 '수집'은 기기 밖으로 보내는 것을 말한다.** 기기에만 저장하고 보내지 않는 것은
수집으로 적지 않는다. 이 앱에서 그런 데이터가 둘 있다(아래 2항).

## 1. 수집·공유하는 데이터

| Play 데이터 유형 | 수집 | 공유 | 필수/선택 | 목적 | 어디에 |
| --- | --- | --- | --- | --- | --- |
| 위치 > **정확한 위치** | 예 | **예** | 선택 | 앱 기능 | `groups/{gid}/locations/{uid}` (lat, lng, accuracy, at) |
| 개인 정보 > **이름** | 예 | **예** | 필수 | 앱 기능, 계정 관리 | `users/{uid}.displayName`, `groups/{gid}/members/{uid}.displayName`, `inviteCodes/{code}.memberNames` |
| 개인 정보 > **이메일 주소** | 예 | 아니요 | 필수 | 계정 관리 | Firebase Authentication, `users/{uid}.email` |
| 개인 정보 > 사용자 ID | 예 | 아니요 | 필수 | 앱 기능, 계정 관리 | Firebase Auth uid (문서 경로와 `senderUid`, `receiverUids`) |
| 메시지 > **기타 인앱 메시지** | 예 | **예** | 선택 | 앱 기능 | `groups/{gid}/alerts/{id}.message` (내가 적어 둔 안심 메시지) |
| 금융 정보 > **구매 내역** | 예 | 아니요 | 선택 | 앱 기능(구독 한도 적용) | `users/{uid}.entitlement` (productId, state, expiryTime) |
| 기기 또는 기타 ID > **기기 또는 기타 ID** | 예 | 아니요 | 필수 | 앱 기능(푸시 발송) | `users/{uid}/pushTokens/{token}`, `members/{uid}.pushToken` (FCM 토큰) |
| 앱 활동 > 기타 사용자가 생성한 콘텐츠 | 예 | **예** | 선택 | 앱 기능 | 그룹 이름(`groups/{gid}.name`) |

### 각 줄에 대한 메모

**정확한 위치 — '선택'으로 적는 이유.** 위치 공유는 이 앱의 중심 기능이지만, 동의하지
않아도 앱을 쓸 수 있다. 그룹에 들어가지 않고 안심 메시지만 보낼 수 있고, 동의를 철회해도
앱이 동작한다. Play 의 '선택'은 '사용자가 주지 않아도 앱을 쓸 수 있는 데이터'를 말하므로
선택이 맞다. `확인 필요`: 그룹에 참여하려면 위치 제공 동의가 **반드시** 필요하다
(동의하지 않으면 구성원이 되지 않는다 — `firestore.rules`). '그룹 참여라는 기능 하나에는
필수'인 셈이라, Console 의 기준으로 '필수'가 맞는지 확인할 것. 모호하면 **필수**로 적는 쪽이
안전하다(사용자에게 더 넓게 알리는 방향).

**'대략적인 위치'를 적지 않은 이유.** 매니페스트에 `ACCESS_COARSE_LOCATION` 이 있지만
저장하는 값은 Fused Location Provider 가 준 좌표 하나다. 정확한 위치로 적고 대략적인
위치는 적지 않는다. `확인 필요`: 권한을 선언했으면 둘 다 적어야 하는지 확인할 것.
둘 다 적는 것이 사용자에게 더 넓게 알리는 방향이라 모호하면 둘 다 적는다.

**'공유'로 적는 이유 — 이 양식에서 가장 헷갈리는 자리다.** Play 의 '공유'는 데이터를
제3자에게 전달하는 것이고, '사용자가 직접 시작한 전달로서 사용자가 그 전달을 예상할 수
있는 경우'는 공유에서 빼도 된다는 설명이 있다. 이 앱의 위치 전달은 사용자가 [공유 시작]을
눌러 시작하고, 받는 사람 목록을 동의 화면에서 보여 준다. 그래서 '공유 아니요'로 적을
여지가 있다.

그래도 **예로 적는다.** 이유는 두 가지다.

1. 위치정보법은 이것을 분명히 **제3자 제공**으로 보고, 그래서 제공 동의를 따로 받고
   매회 통보하고 기록을 남기게 되어 있다(제19조). 같은 사실을 Play 양식에서는 '공유
   아니요'로 적으면 두 설명이 어긋난다.
2. 적게 알리는 쪽으로 틀리면 사용자가 모르는 일이 생기고, 넓게 알리는 쪽으로 틀리면
   사용자가 더 알게 된다. 이 앱에서는 늘 후자를 고른다(CLAUDE.md 원칙 2).

`확인 필요`: Console 양식에 '다른 사용자에게 공유'라는 선택지가 따로 있는지 확인할 것.
있으면 그것을 고른다.

**안심 메시지를 '메시지 > 기타 인앱 메시지'로 적는 이유.** 사용자가 직접 쓴 글이고
(`message` 필드) 그룹 구성원에게 전달된다. 분량이 적어서 빠뜨리기 쉬운 항목이다.

**그룹 이름을 적는 이유.** 사용자가 지은 이름이고 초대 코드를 받은 사람이 참여 전에
볼 수 있다(`inviteCodes/{code}.groupName`). 사소해 보이지만 '사용자가 만든 콘텐츠가
다른 사람에게 보인다'는 사실 그대로 적는다.

**구매 내역.** 결제는 Google Play 가 처리하고 카드 정보는 앱에 들어오지 않는다. 우리
서버에 남는 것은 '어떤 상품을, 어떤 상태로, 언제까지' 세 가지다(`entitlement`).
구매 토큰은 Firestore 에 저장하지 않는다(해시만 쓴다 — 5단계 devlog).

**비밀번호** — `확인 필요`. 이메일 가입 비밀번호는 Firebase Authentication 이 보관하고
우리 Firestore 에는 없다. Play 의 데이터 유형 목록에 '비밀번호' 항목이 보이지 않아서
어디에 적어야 하는지(또는 적지 않아도 되는지) 확인하지 못했다. Console 양식을 보고
정한다. 추측으로 적지 않는다.

## 2. 수집으로 적지 않는 것 (기기 안에만 있다)

| 데이터 | 어디에 | 왜 수집이 아닌가 |
| --- | --- | --- |
| **재난문자 알림 내용**(본문 앞 60자, 본문 해시, 패키지 이름, 문자 종류, 재난 유형) | Room `alert_events` 테이블, 30일 보관 | 기기 밖으로 보내지 않는다. `AlertEventEntity` 주석에 그 사실을 적어 두었고, Firestore 스키마에 이 필드가 없다 |
| 내 위치 제공 기록 사본 | Room `provision_records`, 180일 보관 | 같은 내용이 서버에도 있고(`provisionLogs`) 그쪽은 아래 3항에 적었다. 기기 안 사본 자체는 보내지 않는다 |
| 받은 알림 패키지 기록(디버그 빌드 전용) | Room, 디버그 빌드에만 존재 | 릴리스 빌드(AAB)에 들어가지 않는다 |

**재난문자 본문을 서버로 보내지 않는 것은 설계다.** 서버로 보내는 안심 메시지에는
문자 종류(`severity`)와 재난 유형(`type`)만 들어간다. 본문을 보내면 '내 휴대폰이 어떤
재난문자를 받았는지'가 그대로 서버에 쌓이고, 그것은 사실상 거주지 정보다.

**다른 앱의 알림은 저장하지 않는다.** 알림 접근 권한은 모든 알림을 받을 수 있지만,
허용 목록(`AlertPackages`) 밖의 알림은 서비스 안에서 곧바로 버린다(CLAUDE.md 원칙 4).

## 3. 서버에 남지만 사용자 데이터가 아닌 것

| 데이터 | 메모 |
| --- | --- |
| 동의 기록(`users/{uid}.consents`) | 동의 항목·시각·약관 버전. 법령상 남겨야 하는 기록이다 |
| 제공 내역(`groups/{gid}/provisionLogs`) | 위치정보법 제19조③. uid, 세션, 목적, 받은 사람 uid, 시각. **좌표가 없다** |
| 공유 상태(`members/{uid}.sharing`) | 지금 공유 중인지와 끝나는 시각 |

`확인 필요`: 위 세 가지를 Play 양식의 어느 유형으로 적을지. 동의 기록과 제공 내역은
'사용자 ID + 시각'이라서 위에 적은 '사용자 ID' 줄에 포함되는 것으로 보았다.
Console 에 '앱 활동 > 앱 상호작용' 같은 유형이 있으면 거기에 적는 것도 생각한다.

## 4. 보안 관행 (Security practices)

| 질문 | 답변 | 근거 |
| --- | --- | --- |
| 데이터가 전송 중에 암호화되나요? | **예** | Firebase SDK 는 HTTPS/TLS 로만 통신한다. 앱에 평문 HTTP 가 없다 |
| 사용자가 데이터 삭제를 요청할 수 있나요? | **예** | 앱 안(설정 > 계정 > 계정 삭제)과 웹 페이지 양쪽 |
| 계정 삭제 URL | `[삭제 안내 URL]` | `docs/site/account-deletion.md` 를 Pages 로 공개한 주소 |
| 개인정보 처리방침 URL | `[처리방침 URL]` | `docs/site/privacy-policy.md` 를 Pages 로 공개한 주소 |
| Google Play Families 정책을 준수하나요? | 해당 없음 | 아동 대상 앱이 아니다([app-content.md](app-content.md)) |
| 독립적인 보안 검토를 받았나요? | **아니요** | 받지 않았다. 받지 않은 것을 받았다고 적지 않는다 |

### '전송 중 암호화'에 예라고 적을 수 있는 근거

- 서버로 가는 통신은 Firebase Authentication·Firestore·Cloud Functions·FCM 뿐이고 모두
  TLS 로만 동작한다.
- 앱이 직접 여는 URL 은 Google Play 구독 관리 페이지(`https://`)와 외부 지도 앱을 여는
  `geo:` URI 뿐이다.
- `android:usesCleartextTraffic` 을 켜지 않았다(기본값이 targetSdk 28 이상에서 false).

### '저장 중 암호화'를 적지 않는 이유

Play 양식은 전송 중 암호화만 묻는다. Firestore 는 저장 데이터를 암호화하지만 그것은
Google 의 기반 설명이고, 우리가 추가로 한 암호화는 없다. 하지 않은 것을 적지 않는다.

## 5. 데이터 접근을 좁힌 방법 (양식 밖의 메모)

Play 양식에는 쓰는 자리가 없지만, 심사 문의가 오거나 처리방침을 보완할 때 쓸 내용이다.

- 위치는 **공유 세션 동안에만** 쓴다. 평소에는 위치 코드가 돌지 않는다.
- 60초 간격, 50m 이상 움직였을 때만 기록하고 **이동 경로를 쌓지 않는다**
  (구성원별 마지막 1건만 둔다).
- 세션이 끝나면 마지막 1건만 남기고 24시간 뒤 지운다. 동의를 철회하면 즉시 지운다.
- Firestore 보안 규칙이 '그룹 구성원만, 동의했고 일시중지가 아닌 본인만' 위치를 쓰도록
  막는다. 앱 코드에 버그가 있어도 동의 없는 위치가 올라가지 못한다.
- `users/{uid}.entitlement` 는 서버만 쓴다(규칙으로 클라이언트 쓰기 차단).
