# Firestore 보안 규칙 테스트

`firestore.rules` 가 의도대로 막고 여는지 확인한다.

## 실행

```bash
cd tests/rules
npm install
npm test
```

`npm test` 는 `firebase emulators:exec --only firestore` 로 Firestore 에뮬레이터를 띄운 뒤
`node --test` 를 돌린다.

## 필요한 것

- Node.js 20 이상 (`node --test` 사용)
- **Java 17 이상** — Firestore 에뮬레이터가 JVM 위에서 돈다
- 첫 실행 때 `firebase-tools` 가 에뮬레이터 바이너리를 내려받는다(네트워크 필요)

## 무엇을 확인하나

| 묶음 | 확인하는 것 |
| --- | --- |
| users | 본인 문서만 읽고 쓴다 |
| groups 읽기 | 구성원만 그룹과 구성원 목록을 읽는다 |
| groups 만들기 | 자기만 구성원으로 넣어서 만든다. 남을 미리 넣거나 남을 소유자로 둘 수 없다 |
| 초대 코드로 참여 | 살아 있는 코드가 있어야 들어온다. 만료·없는 코드·다른 그룹 코드는 막는다. 동의하지 않으면 구성원이 될 수 없다. 구성원 문서 없이 목록에만 끼어들 수 없다 |
| 내 공유 상태 | 본인만 일시중지·철회한다. 남의 상태는 그룹을 만든 사람도 못 바꾼다 |
| 소유권과 해산 | 소유권은 남은 구성원에게만 넘긴다. 해산은 만든 사람만 |
| inviteCodes | 코드를 알면 단건 조회는 되고 목록 조회는 막힌다. 발급은 그룹을 만든 사람만 |

## 쓰기 순서에 대한 메모

그룹 참여는 **배치가 아니라 두 번에 나눠** 쓴다.

1. `groups/{gid}/members/{uid}` 를 만든다 — 이때 초대 코드를 검사한다
2. `groups/{gid}.memberUids` 에 자기 자신을 더한다 — 이때 1번 문서가 있는지 본다

보안 규칙은 배치 안의 쓰기를 **배치 전 상태**로 평가한다. 두 쓰기를 한 배치에 넣으면
2번을 검사할 때 1번 문서가 아직 없는 것으로 보여 거부된다.
그룹을 만들 때(그룹 문서 + 만든 사람의 구성원 문서)도 같은 이유로 나눠 쓴다.
앱 코드(`FirestoreGroupRepository`)도 같은 순서로 되어 있다.
